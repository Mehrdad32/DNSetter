# تست DNSetter روی ویندوز

## تست‌های خودکار

پس از دریافت شاخهٔ `master`، با .NET 8 SDK روی ویندوز:

```powershell
dotnet build DNSetter.sln -c Release
dotnet run --project tests/DNSetter.Core.Tests/DNSetter.Core.Tests.csproj -c Release
dotnet run --project tests/DNSetter.Ui.Smoke/DNSetter.Ui.Smoke.csproj -c Release -- ui-preview
```

Core دارای ۱۷ سناریوی regression است و با `dotnet run` اجرا می‌شود. Core و UI smoke از کارت و platform شبیه‌سازی‌شده استفاده می‌کنند و تنظیم واقعی شبکه را تغییر نمی‌دهند. UI smoke ورودی نامعتبر، جدایی DNS پیشنهادی از فعلی، Apply، Automatic و حفظ IPv6 را بررسی می‌کند؛ تصویر پنجرهٔ معمول، کوچک، با متن بزرگ و جدول نتایج را می‌سازد.

در CI، تصاویر در artifact `DNSetter-ui-preview` و خروجی‌های قابل‌اجرای آزمایشی در `DNSetter-win-x64` و `DNSetter-win-x86` قرار می‌گیرند. دانلود پایدار از [Releases](https://github.com/Mehrdad32/DNSetter/releases/latest) انجام می‌شود.

## تست روی کارت واقعی

قبل از شروع، وضعیت همهٔ کارت‌ها را ذخیره کن تا نتیجه و مقادیر لازم برای بازگشت دستی مشخص باشند:

```powershell
Get-DnsClientServerAddress |
    Format-Table InterfaceAlias, InterfaceIndex, AddressFamily, ServerAddresses -AutoSize
```

1. `DNSetter.exe` را اجرا و درخواست Administrator را تأیید کن. با چند کارت متصل، برنامه باید انتخاب صریح کارت را بخواهد.
2. **Adapter details** را بزن. نام، GUID، index، حالت دستی/خودکار و IPv4/IPv6 همان کارت را با تنظیمات ویندوز مقایسه کن. حالت DNS از تنظیم DNS خوانده می‌شود؛ DHCP آدرس IP معیار آن نیست.
3. Cloudflare را انتخاب و **Apply DNS** را بزن. باید `1.1.1.1` و `1.0.0.1` فقط روی همان کارت اعمال شود. خروجی دستور بالا را دوباره مقایسه کن: DNS کارت‌های دیگر و IPv6 باید ثابت باشند.
4. کادر دوم را خالی و یک DNS را اعمال کن. سپس دو آدرس یکسان را وارد کن؛ تنها یک آدرس باید ذخیره شود. ورودی نامعتبر مانند `abc`، `1.1.1.999` یا `::1` باید Apply را غیرفعال کند. IPv4 خصوصی و localhost معتبر هستند.
5. **Automatic DNS** را بزن. فقط DNS IPv4 همان کارت باید خودکار شود. IP و Gateway تغییر نمی‌کنند. DNS دریافتی از DHCP ممکن است همچنان نمایش داده شود؛ روی IP ثابت ممکن است سروری دریافت نشود.
6. بین کارت‌ها جابه‌جا شو و **Refresh** را بزن. نمایش DNS فعلی باید همراه کارت تغییر کند. کارت قطع‌شده قابل مشاهده است ولی Apply/Automatic برای آن غیرفعال‌اند.
7. اگر کارت انتخاب‌شده حذف شد، Refresh نباید کارت دیگری را برای تغییر جایگزین آن کند. انتخاب مجدد باید با کاربر باشد.
8. در پایان، تنظیم اولیهٔ کارت را با آدرس‌های ثبت‌شده یا حالت خودکار بازگردان و خروجی همهٔ کارت‌ها را دوباره مقایسه کن.

**Automatic DNS بازگشت به حالت خودکار است، نه بازیابی تنظیم دستی قبلی.** rollback فقط در صورت شکست همان عملیات تلاش می‌شود. snapshot در حافظه است؛ خاموشی، توقف اجباری یا تغییر هم‌زمان توسط برنامهٔ دیگر تراکنش اتمیک محسوب نمی‌شود. اگر rollback شکست بخورد، خطا نام/شناسهٔ کارت و تنظیم قبلی را نشان می‌دهد.

## رابط کاربری و ابزارها

- فرم اصلی را با Tab و میانبرهای Alt دکمه‌ها بررسی کن. وضعیت عملیات باید در پایین پنجره قابل مشاهده بماند.
- پنجره را کوچک کن؛ اسکرول باید دسترسی به کنترل‌ها را حفظ کند.
- Display Scale برابر ۱۲۵٪، ۱۵۰٪ و ۲۰۰٪ و حالت High Contrast را بررسی کن؛ این بررسی دستی مکمل capture با متن بزرگ است.
- preset جدید ذخیره کن، برنامه را ببند و باز کن؛ داده باید از `list.json` دوباره بارگذاری شود.
- Ping منتخب و همهٔ presetها را اجرا کن. جدول باید پیشرفت داشته باشد و بستن آن ادامهٔ کار را لغو کند. نتایج ICMP سنجش پاسخ DNS نیستند.
- Site reachability فقط پاسخ HTTP سایت Gemini را گزارش می‌کند و دربارهٔ عبور از محدودیت نتیجه‌گیری نمی‌کند.

برای گزارش نتیجه، نسخهٔ برنامه و ویندوز، x64/x86، نوع کارت و وضعیت VPN، نتیجهٔ Apply/Automatic و متن کامل خطا را ثبت کن.
