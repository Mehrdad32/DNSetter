# نسخهٔ ۲ — قدم اول: کارت شبکه و تنظیم DNS

این شاخه نسخهٔ آزمایشی `2.0.0-alpha.2` است. قدم اول، جداکردن Core و اصلاح خواندن، اعمال و بازگشت DNS برای **یک کارت شبکهٔ انتخاب‌شده** است.

## دریافت و اجرا

اگر فایل `DNSetter-v2-core-source.zip` را دریافت کرده‌ای، آن را استخراج کن و در پوشهٔ استخراج‌شده این دستورها را اجرا کن:

```powershell
dotnet build DNSetter.sln -c Debug
dotnet run --project tests/DNSetter.Core.Tests/DNSetter.Core.Tests.csproj -c Release
```

برای دریافت همین شاخه از GitHub، در پوشهٔ ریپو:

```powershell
git fetch origin
git switch --track origin/feat/v2-core-adapter-dns
dotnet build DNSetter.sln -c Debug
dotnet run --project tests/DNSetter.Core.Tests/DNSetter.Core.Tests.csproj -c Release
```

اگر قبلاً همین شاخه را ساخته‌ای، به‌جای دستور دوم `git switch feat/v2-core-adapter-dns` بزن و سپس `git pull --ff-only` را اجرا کن.

فایل `bin\Debug\net8.0-windows\DNSetter.exe` را اجرا کن. برنامه با manifest درخواست Administrator می‌کند. اگر اجرا از Visual Studio مشکل دسترسی داد، همین EXE را مستقیم اجرا کن.

برای اجرای مستقل از SDK، پس از موفق‌شدن CI، از workflow **V2 validation** در تب Actions، artifactهای `DNSetter-v2-core-win-x64` یا `DNSetter-v2-core-win-x86` را دانلود و استخراج کن. این‌ها خروجی تست این مرحله هستند.

## تست روی ویندوز

قبل از شروع، خروجی این دستور را نگه دار تا DNS همهٔ کارت‌ها، از جمله VPN و IPv6، قابل مقایسه باشد:

```powershell
Get-DnsClientServerAddress |
    Format-Table InterfaceAlias, InterfaceIndex, AddressFamily, ServerAddresses -AutoSize
```

1. برنامه را اجرا کن. کارت‌های IPv4 با نام، نوع و وضعیت اتصال نمایش داده می‌شوند. اگر چند کارت متصل باشد، خودت یکی را انتخاب کن؛ برنامه از روی وجود Gateway مسیر اینترنت را حدس نمی‌زند.
2. **Adapter details** را بزن. نام، GUID، index، حالت DNS و آدرس‌های همان کارت را با تنظیمات ویندوز مقایسه کن. حالت DNS از تنظیم DNS خوانده می‌شود؛ فعال‌بودن DHCP برای آدرس IP معیار آن نیست.
3. Cloudflare را انتخاب کن و **Apply DNS** را بزن. باید `1.1.1.1` و `1.0.0.1` روی همان کارت اعمال شود. دستور بالا را دوباره اجرا کن؛ IPv4 کارت‌های دیگر و تنظیم IPv6 باید همان مقادیر قبلی باشند.
4. کادر دوم را خالی کن و با یک DNS، Set را تست کن. بعد دو DNS یکسان وارد کن؛ Core آدرس تکراری را حذف می‌کند.
5. `abc`، `1.1.1.999` یا `::1` وارد کن. دکمهٔ Apply باید غیرفعال شود و تنظیم شبکه تغییر نکند. این مرحله فقط IPv4 را می‌نویسد؛ DNS خصوصی و localhost معتبر هستند.
6. **Automatic DNS** را بزن. فقط DNS IPv4 همان کارت به حالت خودکار برمی‌گردد. آدرس IP، Gateway و IPv6 تغییر نمی‌کنند. ممکن است DNS دریافتی از DHCP همچنان نمایش داده شود؛ این طبیعی است. روی کارت با IP ثابت و بدون DHCP ممکن است DNS خودکار موجود نباشد.
7. بین کارت‌ها جابه‌جا شو و **Refresh** را بزن. DNS فعلی باید همراه کارت تغییر کند. کارت قطع‌شده قابل مشاهده است، ولی Set و Automatic برای آن غیرفعال‌اند.
8. اگر کارت انتخاب‌شده حذف شد، Refresh نباید کارت دیگری را به‌جای آن برای تغییر انتخاب کند. با چند کارت متصل، انتخاب را صریح انجام بده.

**Automatic DNS، تنظیم دستی قبلی را بازیابی نمی‌کند؛ DNS را به حالت خودکار می‌برد.** برای برگرداندن تنظیم دستی بعد از یک Set موفق، آدرس‌های قبلی را دوباره وارد و Set کن. rollback این مرحله فقط برای عملیات ناموفق است و snapshot آن در حافظه نگهداری می‌شود.

نتیجهٔ تست را با نسخهٔ ویندوز، نوع کارت، وضعیت VPN، نتیجهٔ Set/Automatic و متن کامل هر خطا گزارش کن. تست Ping تک‌آدرس و فهرست به‌صورت async اجرا می‌شوند. Ping مشترک و تست دوباره حذف شده‌اند؛ بااین‌حال، سنجش DNS resolution واقعی متعلق به مرحلهٔ بعد است. تست دسترسی سایت فقط HTTP را بررسی می‌کند و دربارهٔ عبور از محدودیت‌ها نتیجه‌گیری نمی‌کند.

## ساختار و رفتار Core

- `DNSetter.Core`: مدل کارت، اعتبارسنجی IPv4، سرویس تغییر DNS و قرارداد مستقل از WinForms و ویندوز.
- `DNSetter.Windows`: خواندن کارت با GUID، خواندن حالت دستی/خودکار از تنظیم IPv4 همان کارت و اجرای `netsh` با index تازه و آرگومان‌های جدا.
- `MainForm`: انتخاب کارت، نمایش وضعیت و فراخوانی async سرویس. هم‌زمان با عملیات، کنترل‌ها و بستن معمول فرم غیرفعال می‌شوند.
- `tests/DNSetter.Core.Tests`: runner بدون وابستگی به پکیج تست؛ **با `dotnet run` اجرا می‌شود، نه `dotnet test`**. هیچ تنظیم واقعی شبکه‌ای را تغییر نمی‌دهد.

قبل از نوشتن، تنظیمات فعلی همان کارت دوباره خوانده می‌شود. پس از اتمام دستور، حالت و ترتیب DNS دستی، به‌همراه آدرس‌های مؤثر IPv4، دوباره بررسی می‌شوند. شکست دستور یا بررسی باعث تلاش برای بازگشت همان کارت به حالت قبلی می‌شود. اگر rollback هم شکست بخورد، نام/GUID کارت و DNS قبلی در خطا می‌آید. خطای پاک‌سازی cache پس از تغییر موفق به‌صورت هشدار گزارش می‌شود.

شکست افزودن DNS دوم، rollback از حالت دستی با بیش از دو DNS، rollback از حالت خودکار، خطای بررسی پس از فرمان، خطای rollback و عملیات هم‌زمان در تست‌های شبیه‌سازی‌شده پوشش داده شده‌اند. این تست‌ها جای اجرای واقعی روی ویندوز را نمی‌گیرند. Force-kill، خاموش‌شدن سیستم و تغییر هم‌زمان شبکه توسط برنامهٔ دیگر، تراکنش اتمیک محسوب نمی‌شوند. DNS مؤثر نیز تضمین نمی‌کند که مرورگر دارای DoH یا سیاست NRPT/VPN از آن استفاده کند.

## قدم‌های بعد از تأیید این مرحله

1. بررسی پاسخ DNS واقعی و نمایش وضعیت/زمان پاسخ DNS؛ Ping مشترک و تست دوباره در alpha.2 حذف شده‌اند.
2. مدیریت providerها و محل ذخیره‌سازی تنظیمات.
3. تأیید UI جدید، تکمیل README و آیکون، سپس Release نهایی x64/x86.

مرجع فرمان‌های ویندوز: [Microsoft Learn — netsh interface](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface).

## تغییرات UI در alpha.2

فرم اصلی با بخش‌های کارت شبکه، DNS و ابزارها بازطراحی شده است. DNS فعلی در کادر read-only قابل کپی دیده می‌شود و ورودی‌ها تنظیم پیشنهادی را نشان می‌دهند. Apply فقط با ورودی معتبر و کارت متصل فعال است. نتیجهٔ موفق عملیات در خود فرم نمایش داده می‌شود. فرم قابل تغییر اندازه است و در اندازه‌های کوچک اسکرول دارد. DPI از PerMonitorV2 استفاده می‌کند؛ حالت High Contrast نیز رنگ‌های سیستم را حفظ می‌کند.

نتایج Ping در جدولی جدا با ردیف‌های ازپیش‌نمایش‌داده‌شده، پیشرفت و وضعیت پاسخ نمایش داده می‌شوند. بستن این پنجره تست‌های باقی‌مانده را لغو می‌کند.

برای تأیید دستی، فرم را با Tab و Alt+میانبر دکمه‌ها بررسی کن، اندازهٔ پنجره را کوچک کن و در Display Scale برابر ۱۲۵٪، ۱۵۰٪ و ۲۰۰٪ ببین که کنترل‌ها قابل دسترسی بمانند.

CI یک smoke check بومی ویندوز با کارت شبکهٔ شبیه‌سازی‌شده اجرا می‌کند و تصاویر `main.png`، `main-compact.png`، `main-large-text.png` و `results.png` را در artifact `DNSetter-v2-ui-preview` قرار می‌دهد. این تصاویر از خود WinForms گرفته می‌شوند؛ دادهٔ شبکهٔ آن‌ها نمونه است.
